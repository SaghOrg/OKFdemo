# Learnings

- **S1 glossary**: Built context/glossary.md (type: glossary) with ~28 canonical-concept sections, each carrying a single greppable 'Aliases:' line: distributor, primary sales, secondary sales (plus a dedicated PRIMARY-vs-SECONDARY callout with direct Karthik-corrects-Vikram citations), scheme discount, variance, credit note, secondary sales feed/DMS, warehouse, nightly load, ODI mapping, stored procedure, server, dashboard, filter control, visual, agent (false-friend OBIEE-vs-ODI sense), SCD2, crore, lakh, Indian business-English register, organisations, a systems-ASR block (ORION/ODI/OBIEE/Control-M/DBLINK/SKU/DELETE_FLAG), places (Baddi/Nashik/Andheri), and a people name-ASR table. Every speaker attribution and every ASR alias was independently confirmed by grepping _sources/ and _build/corpus_text/ directly rather than trusting _canon/terminology_map.csv verbatim, per the stage instructions. Frontmatter validated clean against schemas/concept.schema.json using the repo's own .venv-synth (pyyaml+jsonschema already installed there) after normalizing YAML-parsed dates back to ISO strings (a PyYAML auto-typing artifact, not a real schema violation). generated.by is exactly process:claude-sonnet/glossary; generated.at came from `date -u +%Y-%m-%dT%H:%M:%SZ` (2026-08-23T10:30:54Z). No status field (glossary is stable), no verified field, no PII substrings from the five planted PII locations appear anywhere in the file (grepped for all five marker strings post-write, zero hits), and no 16th named person was introduced (regex-scanned all Capitalized-Capitalized bigrams against the 15-person registry — every hit was a place/org/product name or a documented ASR name-mangling). All /_sources/... paths cited in the body were verified to resolve to real files on disk after fixing one stray '/_sources/meetings/...' placeholder link left over from drafting.

- **S2 tables**: Stage 2 (Tables) transformation complete for three OMS_PROD tables. Key learnings from the schema canon and prose enrichment: (1) INVOICE_HEADER: Master document table with document types (INV, STN, SMP). Critical insight: CREATED_TS is UTC (VAR-002), not IST business date; use INVOICE_DT for reporting. FIN_PROD holds an undocumented UPDATE grant on INVOICE_LINE since 2014. (2) INVOICE_LINE: Line-item detail with SKU/quantity/pricing; schema aligns with INVOICE_HEADER.INVOICE_ID foreign key relationship.
